# A6: Indexes, triggers, user functions and population

Databases are analyzed for their memory use, maximum loads and I/O operations. This components can give a small approximation of the database performance and its parameters. The workload of a database can be analyzed by determining the number of queries executed by the database in a certain period of time, or the average number of queries being executed at a particular instant of time. This execution time and performance is influenced by the cardinality and the estimated growth rate of the database.

### 2.2. Full-text Search Indexes

| Index reference | IDX   |
|-----------------|---------------------------|
| Index relation  | Project  |
| Index attribute | description, company|
| Index type      | GIN |
| Clustering      | No |
| Justification   | To provide full-text search features to look for projects based on matching descriptions or companies. The index type is GIN because the indexed fields are not expected to change often. |
```sql
-- Add column to Project to store computed ts_vectors.
ALTER TABLE Project
ADD COLUMN tsvectors TSVECTOR;

-- Create a function to automatically update ts_vectors.
CREATE FUNCTION project_search_update() RETURNS TRIGGER AS $$
BEGIN
 IF TG_OP = 'INSERT' THEN
        NEW.tsvectors = (
         setweight(to_tsvector('english', NEW.description), 'A') ||
         setweight(to_tsvector('english', NEW.company), 'B')
        );
 END IF;
 IF TG_OP = 'UPDATE' THEN
         IF (NEW.description <> OLD.description OR NEW.company <> OLD.company) THEN
           NEW.tsvectors = (
             setweight(to_tsvector('english', NEW.description), 'A') ||
             setweight(to_tsvector('english', NEW.company), 'B')
           );
         END IF;
 END IF;
 RETURN NEW;
END $$
LANGUAGE plpgsql;

-- Create a trigger before insert or update on Project.
CREATE TRIGGER project_search_update
 BEFORE INSERT OR UPDATE ON Project
 FOR EACH ROW
 EXECUTE PROCEDURE project_search_update();


-- Finally, create a GIN index for ts_vectors.
CREATE INDEX search_idxproj ON Project USING GIN (tsvectors);
```

| Index reference | IDX   |
|-----------------|---------------------------|
| Index relation  | User  |
| Index attribute | username, first_name, last_name |
| Index type      | GIN   |  
| Clustering      | No  |
| Justification   | To provide full-text search features to look for users based on matching username, first_name or last_name. The index type is GIN because the indexed fields are not expected to change often. |
```sql
-- Add column to User to store computed ts_vectors.
ALTER TABLE User
ADD COLUMN tsvectors TSVECTOR;

-- Create a function to automatically update ts_vectors.
CREATE FUNCTION user_search_update() RETURNS TRIGGER AS $$
BEGIN
 IF TG_OP = 'INSERT' THEN
        NEW.tsvectors = (
         setweight(to_tsvector('english', NEW.username), 'A') ||
         setweight(to_tsvector('english', NEW.first_name), 'B') ||
         setweight(to_tsvector('english', NEW.last_name), 'C')
        );
 END IF;
 IF TG_OP = 'UPDATE' THEN
         IF (NEW.username <> OLD.username OR NEW.first_name <> OLD.first_name OR NEW.last_name <> OLD.last_name) THEN
           NEW.tsvectors = (
             setweight(to_tsvector('english', NEW.username), 'A') ||
             setweight(to_tsvector('english', NEW.first_name), 'B') ||
             setweight(to_tsvector('english', NEW.last_name), 'C')
           );
         END IF;
 END IF;
 RETURN NEW;
END $$
LANGUAGE plpgsql;

-- Create a trigger before insert or update on User.
CREATE TRIGGER user_search_update
 BEFORE INSERT OR UPDATE ON User
 FOR EACH ROW
 EXECUTE PROCEDURE user_search_update();


-- Finally, create a GIN index for ts_vectors.
CREATE INDEX search_idxuser ON User USING GIN (tsvectors);
```
