# A5: Relational Schema, validation and schema refinement

The Relational Schema is used to represent the data to be entered into the database and describe how that data is structured in tables.

## 5.1 Relational Schema
| Relational Reference | Relation Compact Notation  |
| -------------------- | -------------------------------------------------------------------------------------------------------------------- | 
| R01 | Authenticated_user (<ins>id_user</ins>, username UK NN,first_name NN,last_name NN, email UK NN, description )| 
| R02 | Admin (id_user -> Authenticated_user) |
| R03 | Team_member (id_user -> Authenticated_user, position NN) | 
| R04 | Notification (<ins>id_notification</ins>, type NN, content NN) | 
| R05 | Member_notification(id_user -> Authenticated_user, id_notification -> Notification)| 
| R06 | Project (<ins>id_project</ins>, name UK NN, description NN, project_Status NN, creation_date NN, current_edit_data NN, company NN) |
| R07 | Member_Project (id_project -> Project, id_user -> Authenticated_use) | 
| R08 | Team (<ins>id_team</ins>, name UK NN, field DF )| 
| R09 | Member_team (id_user -> Authenticated_user, id_team -> Team, is_coordinator DF)| 
| R10 | Comment (<ins>id_comment</ins>, content NN, creation_date NN, current_edit_date NN) |
| R11 | Forum (<ins>id_forum</ins>) |
| R12 | Task (<ins>id_task</ins>, title NN, description NN, creation_date NN, current_edit_date NN, task_status DF) |
| R13 | Task_comment (id_comment -> Comment,id_task -> Task )|
| R14 | Task_history (<ins>id_task_history</ins>) |

Note: UK means UNIQUE KEY, NN means NOT NULL, DF means DEFAULT
