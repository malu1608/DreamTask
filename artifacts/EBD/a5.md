# A5: Relational Schema, validation and schema refinement

The Relational Schema is used to represent the data to be entered into the database and describe how that data is structured in tables.

## 5.1 Relational Schema
| Relational Reference | Relation Compact Notation  |
| -------------------- | -------------------------------------------------------------------------------------------------------------------- | 
| R01 | User (<ins>id_user</ins>, username UK NN,first_name NN,last_name NN, email UK NN, description)| 
| R02 | Admin (id_user -> User) |
| R03 | Team_Member (id_user -> User, position NN) | 
| R04 | Project (<ins>id_project</ins>, name NN, description NN, project_Status NN, company NN, creation_date NN, current_edit_data NN CK creation_date < current_edit_data ) |
| R05 | Member_Project (<ins>id_project</ins> -> Project, <ins>id_user</ins> -> User) | 
| R06 | Notification (<ins>id_notification</ins>, content NN) |
| R07 | Project_Notification (id_notification -> Notification, id_project -> Project) |
| R08 | Member_Notification(<ins>id_user</ins> -> User, <ins>id_notification</ins> -> Notification)| 
| R09 | Team (<ins>id_team</ins>, name UK NN, field NN, id_project -> Project FK)| 
| R10 | Member_Team (<ins>id_user</ins> -> User, <ins>id_team</ins> -> Team, is_coordinator DF)| 
| R11 | Task (<ins>id_task</ins>, title NN, description NN, creation_date NN, current_edit_date NN CK creation_date < current_edit_data, task_status DF, deleted NN DF False, id_team -> Team FK) |
| R12 | Task_Notification (id_notification -> Notification, id_task -> Task) |
| R13 | Task_Member (<ins>id_user</ins> -> User, <ins>id_task</ins> -> Task) |
| R14 | Comment (<ins>id_comment</ins>, content NN, creation_date NN, current_edit_date NN CK creation_date < current_edit_data, id_user -> User FK, id_task -> Task FK, id_team -> Team FK ) |
| R15 | Comment_Notification (id_notification -> Notification, id_comment -> Comment) |

Note: UK means UNIQUE KEY, NN means NOT NULL, DF means DEFAULT, CK means CHECK
